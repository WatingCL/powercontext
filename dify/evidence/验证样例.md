# 验证样例 —— 如何复现「跨会话记仇」

本文件给出评审可直接照做的验证步骤与预期结果。核心验证点：**NPC 在一个全新会话里，
能主动提起此前另一个会话写入 PowerContext 的旧账（恶作剧 / 赊账）**，证明记忆被跨会话持久化并复用。

---

## 前置条件（一次性）

1. 本地启动 PowerContext Server（默认 `http://127.0.0.1:8000`）。
2. 运行初始化脚本预置旧账并拿到作用域 ID：
   ```bash
   py init/powercontext_init.py --new
   ```
   记下打印出的 `PC_SCOPE_ID=scp_xxxxxxxx`。
3. 让 Dify Cloud 能访问本地 8000 端口（二选一）：
   - **公网隧道（Dify Cloud 用）**：`ssh -R 80:localhost:8000 nokey@localhost.run`，
     得到形如 `https://xxxx.lhr.life` 的公网地址；
   - **自托管 Dify**：若 Dify 与 PowerContext 同机，直接用 `http://127.0.0.1:8000`，无需隧道。
4. 在 Dify 导入 `dsl/grudge-npc-chatflow.yml`，把环境变量改成：
   - `PC_BASE_URL` = 上一步可访问的地址（隧道 URL 或 `http://127.0.0.1:8000`）
   - `PC_SCOPE_ID` = 第 2 步打印的 ID
   并配置 DeepSeek 模型供应商的 API Key（`deepseek-v4-pro`）。

---

## 样例 A：新会话翻旧账（读 + 用记忆）

| 项 | 内容 |
|----|------|
| 会话 | **全新会话**（conversation_id 为空，会话内无任何历史消息） |
| 玩家输入 | `掌柜的，好久不见，来壶酒` |
| 预期 NPC 行为 | 主动提起「蟑螂」和/或「赊账」旧账，阴阳怪气但仍在做生意，回复 ≤80 字 |

**实测输出（真实运行，见 evidence/验证证据01）：**
> 哟，张三，可算来了。上回那蟑螂账还没算，赊的酒钱也记着呢。这壶酒，先结旧账再开新坛，不然我怕你又往里头添"料"。

**判定点**：会话内没有历史消息，NPC 却知道蟑螂与赊账 —— 只能来自 PowerContext 跨会话记忆。

---

## 样例 B：本轮发言被写回（写记忆）

样例 A 运行后，检查作用域记忆条目：
```bash
curl -s -X POST http://127.0.0.1:8000/v1/memory/entries/list \
  -H "Content-Type: application/json" \
  -d '{"scope_id":"<你的 PC_SCOPE_ID>","limit":20}'
```
**预期**：返回结果中新增一条 `顾客说：掌柜的，好久不见，来壶酒`（由 `记忆写回` 节点写入，`changed:true`）。

---

## 样例 C：第二个新会话复用样例 B 写入的记忆

1. 再开一个**全新会话**，输入：`掌柜的，我上次说啥来着？`
2. **预期**：NPC 能提到样例 A/B 的互动（说明样例 B 写入的记忆在又一个新会话里被读到并复用）。

---

## 反例对照（可选，强化说服力）

- 用 `init/powercontext_init.py --new` 建一个**空作用域**，把 Dify 的 `PC_SCOPE_ID` 换成它；
- 新会话输入 `掌柜的，好久不见，来壶酒`；
- **预期**：NPC 无旧账可翻，只能按人设泛泛应答（不会凭空捏造蟑螂/赊账），
  与样例 A 形成对照，证明「翻旧账」确实由 PowerContext 记忆驱动，而非模型幻觉。
